# VICTOR VON DOOM — Elden Ring Total Character Conversion

**Codename:** `EMPEROR_DOOM`
**Target game:** *Elden Ring* PC (Steam), patch 1.16+ / Smithbox-compatible regulation
**Runtime:** Offline, EAC disabled (`ModEngine2`)
**Status:** Engineering build package + working project scaffold (see *Scope & Honesty* below)

This project rebuilds four interlocking Marvel power systems inside Elden Ring as a single
coherent character: **Dr. Doom**, **Mjolnir**, **the Odinforce**, and **the six Infinity
Stones** — culminating in the optional **Emperor Doom** state.

It is architected as *one* power framework, not four bolted-together mods. Every ability
routes through a shared resource/control/VFX layer so the systems complement each other
mechanically and visually.

---

## Scope & Honesty (read this first)

Elden Ring total conversions of this size are **multi-person, multi-month asset projects**.
Three classes of work exist, and this repository is explicit about which is which:

| Class | What it is | Delivered here |
|---|---|---|
| **A — Authorable as data/scripts** | `regulation.bin` param edits, EMEVD event logic, HKS control logic, ModEngine2 config, FXR authoring source, install/config system | **Concrete, buildable artifacts** in this repo |
| **B — Authorable but tool-driven** | TAE animation events, FXR compile, FMG text, param import | **Exact specs + source files + step-by-step tool procedures** |
| **C — External DCC assets** | Custom 3D armor/Mjolnir models, rigged animations, textures, bespoke SFX audio | **Exact production specifications** (poly budget, rig, bone map, material channels) — these *cannot* be binary-generated by a text agent and must be produced in Blender/Substance/DAW |

Nothing here fabricates a param name, tool API, or animation ID that wasn't verified against
the live 2025–2026 modding ecosystem. Where a specific field ID must be confirmed against
*your* regulation version or a tool's current release, it is flagged **`[VERIFY]`**.

This is the difference between "a plan" and "a build": you can open Smithbox, run the
massedit scripts in [`params/`](params/), open DarkScript3 on the sources in [`event/`](event/),
drop the [`modengine/`](modengine/) config in place, and have a **functioning skeleton of the
mod running in-game** — then layer the Class-C art assets on top per the specs.

## Install (summary — full steps in docs/07)

1. Install **ModEngine2**; disable EAC (launch offline via `launchmod_eldenring.bat`).
2. Back up your `regulation.bin` (a bad merge corrupts saves — see docs/07).
3. Merge the [`params/`](params/) edits into `regulation.bin` with **Smithbox** massedit.
4. Compile [`event/common_doom.js`](event/common_doom.js) → `common.emevd.dcx` with **DarkScript3**, place in mod's `event/`.
5. Build FXR from [`fxr/`](fxr/), pack with **WitchyBND**; add Class-C assets per docs/06.
6. Point `config_victorvondoom.toml` at your mod folder; launch.
